# Customer development

## When this module loads

- "How many people should I talk to?"
- "How do I know if I'm right?"
- "I want to test this before I build it"
- "What should I build first to find out?"
- Phases 01, 02, 03

## The lens

Nothing inside the building is a fact. The founder's conviction, the team's
agreement, the deck's logic — all of it is hypothesis until it meets a stranger
who owes you nothing.

So the job is not to gather opinions until confidence arrives. It is to write
down what you believe, pick the belief that would hurt most to be wrong about,
and design the smallest thing that could kill it this week. A test that takes a
month is not a test; it is a project with a question attached.

The discipline is in the ordering. Founders test the assumption they are most
comfortable with and call it progress (rule of thumb). The riskiest assumption is usually the
one they have been avoiding naming (rule of thumb), because naming it makes it testable, and
testable means it might lose.

## Questions to ask, in order

1. Which of the things you just told me came from outside your own head?
2. What do you believe most strongly that you have never checked?
3. If that belief turned out to be wrong, what else falls over with it?
4. What is the smallest test that could prove you wrong this week?
5. What result would make you change course, decided before you run it?
6. How are you finding the people you talk to?
7. How many of them did you already know?
8. What have you learned in the last two weeks that you did not know before?

## Red flags in the answer

- "I'll know it's working when it feels right." — No pass number, so no test.
- "I'm testing whether people like the design." — Testing the comfortable
  assumption, not the risky one.
- "All of them were people I know." — A friends-and-family signal.
- "I'll build it and see what happens." — A six-month test with no exit
  condition.
- "I already know the answer, I just need to confirm it." — That is not a
  test, that is a search for permission.
- A pass number invented after the result came in. Draw the line first.

## The evidence this module accepts

Scored against `references/evidence-rubric.md`. This module is trying to reach
**score 2** on the riskiest assumption specifically, not on everything.

- **Score 2:** a test that was designed with a pass number before it ran, run
  on people the founder did not already know, with the result written down
  whichever way it went.
- **Score 3:** the test required someone to commit something — money, a
  booking, a signature.
- **Score 0:** any test whose pass condition was decided afterwards.

A test the founder could not have failed produces no evidence at any score.

## Output

`references/artifacts/experiment-card.md` — one assumption, the if-then
hypothesis, the test, the pass number decided in advance, the result, the
score.
