# Zip Build Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `pro/dist/startup-board-pro.zip` with forward-slash path separators so install routes 1 and 2 work on macOS and Linux, and add a checker assertion that fails on any backslash entry so the defect cannot return.

**Architecture:** A new `pro/build-zip.sh` replaces the PowerShell `Compress-Archive` command that currently lives only in the task-13 plan text. It builds the archive with bsdtar/libarchive (writes `/`, ships with Windows 10+, macOS 10.15+, most Linux) and falls back to Info-ZIP `zip`; it refuses to build if neither is present rather than reaching for PowerShell. A new `check_zip` group in `pro/evals/check.sh` reads the archive's stored entry names and fails on any backslash, on payload drift from the source tree, and on an unreadable archive. The builder's last step is that checker, so a bad zip cannot be produced silently.

**Tech Stack:** POSIX `sh`, bsdtar (libarchive) or Info-ZIP `zip`, Info-ZIP `unzip` or Python `zipfile` for verification. No new dependencies installed.

**Spec:** `docs/superpowers/specs/2026-10-12-startup-board-pro-design.md` — this plan amends its section 13 (packaging and distribution), which specified the PowerShell build command. Decisions are recorded in `docs/superpowers/2026-10-12-decisions.md`.

## Global Constraints

- Shell scripts are POSIX `sh`, opening `#!/usr/bin/env sh` and `set -u`, matching `pro/evals/check.sh`. No bash-only syntax.
- No new dependency is installed. The build uses a tool already on the machine or refuses.
- `.gitattributes` pins `eol=lf` for `.sh`, `.md` and `.json`. `pro/build-zip.sh` is a `.sh` file and inherits that rule; do not add a `.gitattributes` entry.
- The zip payload is exactly `find . -type f -not -path './dist/*' -not -name AUDIT.md` run from `pro/` — currently 112 files. The payload set must not change in this plan.
- The shipped version stays **2.0.0**. Nothing has reached a buyer: `gh release list --repo shuvgenai/startup-board-pro` is empty, the repo is private, and `**/dist/*.zip` is gitignored so no zip was ever committed. The skill files are byte-identical before and after; only the archive container changes. No CHANGELOG entry, no manifest version bump.
- `pro/dist/startup-board-pro.zip` stays gitignored. It is a build artifact, regenerated by the script.
- The checker must stay correct in all three install layouts it already supports: the build tree (`pro/`), an extracted zip (`SKILL.md` at top level), and the distribution repo (`skills/startup-board-pro/`).

## Review Focus

- **Neither bsdtar nor Info-ZIP `zip` on the machine.** The builder must stop with a named error and a hint, never silently emit nothing and never fall back to PowerShell. Test in Task 2, Step 4.
- **A stale archive already at the output path.** `zip -r` appends to an existing archive, so a rebuild after a source file is deleted would keep the deleted file in the zip. The builder must remove the output first. Test in Task 2, Step 6.
- **A fresh clone or a buyer's install, where no zip exists.** `check_zip` must report a skip, not a failure, or the suite a buyer re-runs reports a defect that is not there. Test in Task 1, Step 4.
- **No `unzip` and no working Python.** The guard has no way to read entry names and must fail saying so. Printing `ok` with no reader would be the original bug wearing a green shirt. Test in Task 1, Step 5.
- **bsdtar stores directory entries (`references/`, `phases/`) that `Compress-Archive` omitted.** The payload comparison must drop entries ending in `/` or it reports spurious extras against the source file list. Test in Task 2, Step 5.

- [ ] **Step 1: Write the guard**

Insert this function into `pro/evals/check.sh` immediately after the closing `}` of `check_cases()` and before the `case "${1:-all}" in` line:

```sh
# The installable zip for routes 1 and 2. It is a build artifact: gitignored,
# absent from a fresh clone and from a buyer's install, so an absent zip is a
# skip and a present one is asserted hard.
#
# Windows PowerShell 5.1 Compress-Archive stored 107 of 112 entries with "\"
# separators, against ZIP spec 4.4.17.1, which requires "/". Info-ZIP unzip
# silently repairs that on read and macOS Archive Utility does not: there it
# extracts one flat file named "references\fit-ladder.md", and every link in
# SKILL.md resolves to nothing. The original build verified the zip with
# PowerShell Expand-Archive, the same pair that wrote the bug, so the verify
# could never see it. Hence this group reads the stored names, not an extract.
check_zip() {
  _zip="${1:-$PKG/dist/startup-board-pro.zip}"
  if [ ! -f "$_zip" ]; then
    ok "no zip at dist/startup-board-pro.zip (build artifact; run ./build-zip.sh to make one)"
    return
  fi
  _names=""
  if command -v unzip >/dev/null 2>&1; then
    _names=$(unzip -Z1 "$_zip" 2>/dev/null)
  fi
  if [ -z "$_names" ] && [ -n "$PY" ]; then
    _names=$("$PY" -c 'import sys,zipfile;print("\n".join(zipfile.ZipFile(sys.argv[1]).namelist()))' "$_zip" 2>/dev/null)
  fi
  if [ -z "$_names" ]; then
    fail "cannot read zip entry names from $_zip (no unzip and no working interpreter, or the archive is corrupt)"
    return
  fi

  _bs=$(printf '%s\n' "$_names" | grep -c '[\]' || true)
  if [ "$_bs" -eq 0 ]; then
    ok "zip stores no backslash path separators"
  else
    fail "zip stores $_bs entries with backslash separators (ZIP spec 4.4.17.1 requires /); rebuild with ./build-zip.sh"
  fi

  # Entries ending in / are directory records. bsdtar writes them and
  # Compress-Archive did not, so compare files only.
  _zip_files=$(printf '%s\n' "$_names" | sed 's|\\|/|g' | grep -v '/$' | LC_ALL=C sort)
  _src_files=$(cd "$ROOT" && find . -type f -not -path './dist/*' -not -name AUDIT.md | sed 's|^\./||' | LC_ALL=C sort)
  if [ "$_zip_files" = "$_src_files" ]; then
    ok "zip payload matches the source tree ($(printf '%s\n' "$_src_files" | grep -c .) files, nothing missing, nothing extra)"
  else
    fail "zip payload differs from the source tree; rebuild with ./build-zip.sh"
    printf '%s\n' "$_src_files" > "${TMPDIR:-/tmp}/sbp-src.$$"
    printf '%s\n' "$_zip_files" > "${TMPDIR:-/tmp}/sbp-zip.$$"
    diff "${TMPDIR:-/tmp}/sbp-src.$$" "${TMPDIR:-/tmp}/sbp-zip.$$" | sed 's/^/      /'
    rm -f "${TMPDIR:-/tmp}/sbp-src.$$" "${TMPDIR:-/tmp}/sbp-zip.$$"
  fi

  for _x in AUDIT.md dist/ _reference/ .git/; do
    if printf '%s\n' "$_zip_files" | grep -q "^$_x"; then
      fail "zip leaks $_x"
    else
      ok "zip excludes $_x"
    fi
  done

  if command -v unzip >/dev/null 2>&1; then
    if unzip -p "$_zip" SKILL.md 2>/dev/null | head -1 | grep -q '^---'; then
      ok "zip SKILL.md opens with a frontmatter fence"
    else
      fail "zip SKILL.md has no opening frontmatter fence"
    fi
  fi
}
```

- [ ] **Step 1: Write the builder**

Create `pro/build-zip.sh`:

```sh
#!/usr/bin/env sh
# Build the installable zip for install routes 1 and 2.
#
# Why not PowerShell. Compress-Archive on Windows PowerShell 5.1 writes "\"
# as the entry separator, against ZIP spec 4.4.17.1 which requires "/".
# Info-ZIP unzip repairs that on read, so a build verified with Expand-Archive
# or with unzip looks clean, while macOS Archive Utility extracts one flat
# file named "references\fit-ladder.md" and every link in SKILL.md dies.
# bsdtar/libarchive writes "/" and ships with Windows 10+, macOS 10.15+ and
# most Linux. Info-ZIP zip is the fallback. If neither is here, this script
# refuses: a wrong archive is worse than no archive.
set -u
ROOT="$(cd "$(dirname "$0")" && pwd)"
OUT="$ROOT/dist/startup-board-pro.zip"

# Everything in the skill folder except the dist/ output directory and the
# internal audit. Matches the payload assertion in evals/check.sh.
MEMBERS="SKILL.md INSTALL.md LICENSE CHANGELOG.md README-PRO.md .claude-plugin evals phases references"

for _m in $MEMBERS; do
  [ -e "$ROOT/$_m" ] || { echo "FAIL: $_m is missing from $ROOT; nothing was built" >&2; exit 1; }
done

# A libarchive tar, by any of its names. GNU tar is also called "tar" and
# cannot write zip at all, so check what answers rather than trusting the name.
TAR=""
for _c in bsdtar tar /c/Windows/System32/tar.exe /usr/bin/bsdtar; do
  command -v "$_c" >/dev/null 2>&1 || continue
  if "$_c" --version 2>/dev/null | grep -qiE 'bsdtar|libarchive'; then TAR="$_c"; break; fi
done

mkdir -p "$ROOT/dist" || exit 1
# zip -r appends to an existing archive, so a file deleted from the source
# would survive a rebuild. Remove the output first, on every path.
rm -f "$OUT"

cd "$ROOT" || exit 1
if [ -n "$TAR" ]; then
  echo "building with $("$TAR" --version 2>/dev/null | head -1 | cut -d' ' -f1-2)"
  "$TAR" -a -c -f "$OUT" $MEMBERS || { echo "FAIL: archive write failed; removing partial output" >&2; rm -f "$OUT"; exit 1; }
elif command -v zip >/dev/null 2>&1; then
  echo "building with Info-ZIP zip"
  zip -q -r -X "$OUT" $MEMBERS || { echo "FAIL: archive write failed; removing partial output" >&2; rm -f "$OUT"; exit 1; }
else
  echo "FAIL: no spec-compliant zip writer found. Need bsdtar (libarchive) or Info-ZIP zip." >&2
  echo "      Windows 10+ ships bsdtar at C:\\Windows\\System32\\tar.exe; macOS 10.15+ ships it as tar." >&2
  echo "      Do NOT substitute PowerShell Compress-Archive: it writes backslash separators." >&2
  exit 1
fi

echo "wrote $OUT"
# The build is not finished until the guard passes.
sh "$ROOT/evals/check.sh" zip
```

5.1 `Compress-Archive` wrote them that way, against ZIP spec section
